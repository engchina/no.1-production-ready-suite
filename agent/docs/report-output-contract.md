# 参照付きレポートの出力契約

参照付きレポートは、調査の順番を決める workflow ではなく、回答の組み立てと保存の形式です。Agent は必要な資料、SQL、追加の確認を途中の結果から選びます。確認状況の表示と展開後の文字数はプログラムが扱います。

## 設定と公開版

Agent の `output_contract` は任意の版の項目です。未設定の Agent と既存の実行は、従来の自由な回答を使います。設定を変更した場合は、新しい版を公開して利用者の実行へ反映します。以前の公開版の設定は変わりません。

Agent の作成・更新 API に、次の形式で明示できます。数値は説明用であり、製品の既定の回答文字数ではありません。

```json
{
  "output_contract": {
    "mode": "referenced_report",
    "budget": {
      "metric": "expanded_markdown_codepoints",
      "soft_target": 2000,
      "hard_max": null
    }
  }
}
```

- `soft_target` は目標です。超過は目標達成と扱わず、超過した状態と残りの量を返します。
- `hard_max` は利用者が明示した厳密な上限です。超えた案は回答として確定できません。
- `budget` を省略した場合、文字数の契約は設定しません。
- 目標と上限を併用する場合、目標は上限以下にします。
- 初期の形式では、既存の `output_fields` と同時に設定できません。既存の設定を暗黙に消したり、別の形式へ切り替えたりしません。

予算は公開した設定から決まり、モデルの回答案の引数では増やせません。自然言語の語の一覧や正規表現で、目標と厳密な上限を推測する処理はありません。

この契約は、Agent が任意の業務ツールを直接指定する機能ではありません。外部のツールは引き続き Skill の宣言と実行時の権限で決まります。回答案を作る内部の能力も、取消、引数検証、ポリシー、実行予算、実行の所有者と排他の確認を通ります。

## 確認状況

許可された NL2SQL の保存済み schema を取得すると、その実行の中だけで有効な短い列参照を付けます。モデルは確認したい列の参照と、必要なら取得結果の参照だけを選びます。列の存在、取得の有無、NULL などの判定文は受け付けません。

確認状況の節はプログラムが生成します。特に、対応する取得結果を確認できないことを、データベースに列や値がないことへ置き換えません。

- 保存された定義で列を確認できても、対応する結果を結び付けられなければ、結果は未確認です。
- 部分的な定義、古い状態、由来が不明な結果から、不存在や未照会を推測しません。
- NULL や 0 行は、その取得結果の範囲の事実です。元の表全体に値がないという意味ではありません。
- 短い参照は取得時に固定し、圧縮や同じ実行の再開で振り直しません。他の実行の参照を流用しません。

確認節の列の識別名は JSON 表記です。引用の記号などを含む名前は、別の参照として読み取られないようにエスケープします。表示の JSON から元の名前を復元でき、保存した列名と SQL 結果の見出しは変更しません。

この保証は、プログラムが生成する確認状況の節のものです。考察やメールなど、モデルが書く自由な文章の真偽や因果関係を、すべて意味検査する機能ではありません。

## 回答案のプレビューと確定

モデルは本文、既存の結果表の行列選択、確認状況を構造化した案として渡します。プログラムは資料とデータの参照を検証し、必要な本文の変換を終えてから、ブロック別のコスト、合計、残り、目標や上限との対応を返します。

展開した表・セル・確認節へ、識別子の書き換えや別の参照の再展開を重ねません。列名やデータの字面に参照のような文字が含まれても、モデルが明示した資料の引用とは区別します。通常の自由回答の処理は変更しません。

プレビューには `A1` のような、その実行に固定した短い番号を付けます。最終回答ではこの番号だけを選び、保存済みの本文をそのまま確定します。モデルが最後に数字や確認状況を書き直す段はありません。内部のハッシュをモデルへ書き写させることもありません。

同じ処理の復元は同じ番号に対応させます。別の案は別の番号とし、前の案を上書きしません。未知の番号、実行の不一致、壊れた保存状態、厳密な上限の超過は、自由な回答へ暗黙に切り替えて成功にしません。完了済みの調査ツールは再実行せず、結果を保持します。

## 何の文字数か

`expanded_markdown_codepoints` は、参照と本文の変換を終えた Markdown 本文の Unicode codepoint 数です。短い参照文字列や、モデルが生成した token 数とは区別します。確認状況の節も含め、確定後に本文を追加・展開して計数から外れることがないようにします。

この指標を、画面の可視文字数と同じとは扱いません。Markdown の区切り、資料の参照表記、画面が付ける操作部品や参考情報には、それぞれ別の長さがあります。画面の受入では、実際の本文と付随要素を区別して確認します。

文字数の上限で行、列、値を黙って切り捨てません。上限を理由に最終回答を自動で再生成したり、完了した SQL や資料取得を再実行したりする処理もありません。Agent は同じ実行の中でプレビューを見て、必要な情報を保つ案を選びます。モデルの出力 token、総 token、呼出回数、時間の予算は従来どおり別に適用します。
