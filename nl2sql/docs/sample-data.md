# 業務別サンプルデータ

「データ準備 → サンプルデータ管理」で、試したい業務を選びます。画面に表示される対象 SQL と確認語を確認してから取り込みを実行してください。種類や操作を変えると確認語は解除されます。

| 種類 | 内容 | クエリの例 |
|---|---|---|
| 人事サンプルデータ | 部署10件・社員12件・プロジェクト10件、結合ビュー2個 | 部署ごとの社員数と平均給与を知りたい |
| 売上サンプルデータ | 顧客3件・商品3件・受注6件、明細ビュー1個 | 2025年4月から6月の出荷済み売上金額を月別に集計したい |
| 問い合わせサンプルデータ | 顧客3件・問い合わせ分類3件・対応履歴6件、明細ビュー1個 | 未解決の問い合わせ件数を分類別に知りたい |

データはすべて架空です。売上は1受注につき1商品とし、金額は円で保持します。問い合わせは受付日・解決日・対応状況・優先度を持ち、未解決の解決日は NULL です。新しいサンプルの日付は2025年4〜6月に固定しています。

取り込み対象は「すべて」「テーブル」「ビュー」「データ」から選べます。ビュー・データだけを取り込む場合は、先に同じ種類のテーブルを作成してください。Oracle では既存オブジェクト・主キーの重複をスキップする既存の動作を使います。

削除は選択した種類のテーブル・ビューおよび格納データ全体を対象とします。別の種類のサンプルは保持します。サンプル表に追記したデータも削除対象です。対象は現在の接続スキーマで、別スキーマの同名オブジェクトは対象外です。

取り込み後は「業務プロファイル管理」で対象の表・ビューをプロファイルに追加し、SQL 生成画面から選択してください。プロファイルは自動作成しません。Oracle では取り込み・削除の後に対象のスキーマ情報を更新するジョブを投入し、完全更新が必要な場合は画面で案内します。

## API と互換性

- `GET /api/nl2sql/sample-data?dataset=hr|sales|inquiries`：選択したサンプルの SQL・対象・確認語・導入状態。
- `POST /api/nl2sql/sample-data/import` / `POST /api/nl2sql/sample-data/delete`：既存 body に `dataset` を追加。`step`、`confirmation`、`reason` は従来どおり。
- `dataset` の省略は `hr`。人事サンプルの既存名 `DEPARTMENT` / `EMPLOYEE` / `PROJECT` / `V_EMP_DEPT` / `V_DEPT_PROJECT` と確認語 `SQL_ASSIST_SAMPLE` は維持します。
- 売上の確認語は `NL2SQL_SALES_SAMPLE`、問い合わせは `NL2SQL_INQUIRY_SAMPLE`。別種類の確認語では実行できません。未定義の `dataset` は `422` です。
- 新規オブジェクトは `SAMPLE_NL2SQL_` で始まる専用名です。システム内部用 `NL2SQL_` の非表示・操作禁止ルールの対象に入らない業務サンプル名を使い、既存の可視性ルールは維持します。
- 操作権限は `nl2sql.sample_data.manage`。API と domain service で認可を強制します。
- ローカルの決定論ランタイムは従来どおりカタログ状態を更新します。実テーブルへの SQL 適用は Oracle ランタイムで実施します。

固定定義は `backend/app/features/nl2sql/sample_datasets.py`、SQL は隣接する `sample_data/`、日本語の表示は `frontend/src/lib/i18n.ts` で管理します。
