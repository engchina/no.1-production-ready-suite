# 実行履歴（Run history）の型

> 3 製品（RAG・NL2SQL・Agent）の「実行履歴」（サイドナビの「AI 活用」の下。アイコン `History`）の一覧と詳細の正本（#1955）。
> 部品は `@production-ready/ui` の `RunHistoryTable` / `RunHistoryToolbar` / `RunStatusBadge` / `RunSummary` / `RunTimeline` / `RunDetailSection` / `RunDetailLayout`（design-system README §4「実行履歴」、components-reference「実行履歴」）。
> 一覧の基準（件数・ページ送り・ツールバー・読み込み中）は [page-archetypes.md](./page-archetypes.md)、絞り込みの部品は #1933（`FilterSelect`）、見え方（実行者・会話の持ち主）は #1954 と backend-standard.md「「AI 活用」の下の機能のデータの見え方」。

## 0. なぜ決めたか

3 製品の実行履歴は別々に作られ、見た目と使い方がそろっていなかった（2026-10-15 に Playwright で棚卸し。#1955 段 1 の PR に画面の画像と表）。

| | RAG（#1890） | NL2SQL（#1946） | Agent（#1897） |
|---|---|---|---|
| 一覧 → 詳細 | 全幅の詳細（`/history/<run_id>`） | 左の行リスト + 右の詳細のペイン（同じ画面） | 全幅の詳細（`?id=<run_id>`） |
| 一覧の形 | `DataTable`（質問・回答・検証・状態・所要時間・日時・利用者） | 手書きの行リスト（質問・日時・エンジン・所要時間・評価のバッジ） | `DataTable`（目標・利用者・起点・状態・操作） |
| 状態の絞り込み | 欄の上にラベルのある「種類」の選択欄 + 状態の `ToggleChip` | 評価・安全性の選択欄 | 状態の `ToggleChip`（6 つ） |
| 詳細の構成 | 概要 → タブ（結果 / 処理の経過 / フィードバック） | 見出し → タブ（概要 / SQL） | 概要 → 段 → 承認 → ツール → 成果物 → イベント |
| 時間 | 段の表（`DataTable`） | 時間の内訳の数字 | 段ごとのバッジ |

## 1. 決めたこと（推奨で確定。2026-10-15）

| 項目 | 決定 | 採らなかった案と理由 |
|---|---|---|
| 一覧 → 詳細 | **一覧 → 全幅の詳細の画面**（URL で開ける。「一覧へ戻る」で絞り込み・ページ・選んだ行を保って戻る）。3 製品とも同じ。NL2SQL の分割ペインはやめる | **右の詳細のペイン / peek**（LangSmith・Langfuse）: 長い回答・根拠・SQL・処理の経過を読むには幅が足りない（NL2SQL の 1280px で詳細のペインは約 560px）。375px では結局別の画面になる。**一覧の行の展開**（Carbon の expandable row）: 中身が大きく、表の高さが暴れる |
| 詳細の URL | 製品の画面の URL のまま、実行 ID で 1 対 1（Agent `?id=<run_id>`、RAG `/history/<run_id>`、NL2SQL は `?id=<run_id>` にする）。題名のリンクは `href` 付き（新しいタブで開ける） | URL の形を 3 製品で 1 つにする: 利用者に見えず、ルーターの作り直しの費用に見合わない |
| 一覧の列 | **質問（リンク）/ 対象 → 状態 → 種類 → 実行者 → 開始日時 → 所要時間 →（token / 費用）→（製品の列 2 つまで）→ 操作** | **状態を先頭**（GitHub・Phoenix）: 行の見出し（`rowHeader`）は題名で、page-archetypes §0-7 の「先頭セルの対象名のボタン」と、狭い画面で残す 1 列が題名になる。状態は 2 列目に固定して縦に見比べられる |
| 質問の列の名前 | 3 製品とも「質問」（root AGENTS.md「言語」）。Agent の依頼も「質問」 | 「目標」（Agent）: 3 製品で同じ機能の文言は同じにする |
| 時刻 | **絶対時刻**「2026/10/15 09:12」（詳細は秒まで）。`<time dateTime>` | 相対時刻（「3 分前」。Langfuse・Vercel）: 監査の記録・ほかの画面の時刻と見比べる業務で、相対時刻は書き写せない |
| 状態 | 共通の 7 つ（待機中・実行中・応答待ち・完了・ブロック・失敗・停止）を `RunStatusBadge`（色 + 形の違うアイコン + 文言）。実行中もアイコンは回さない | 実行中のバッジに `Spinner`（Vercel は点を動かす）: 一覧に動くものが並ぶと読みにくく、5 秒ごとの再取得で十分に変わる。処理の経過の実行中の段だけ `Spinner` |
| 絞り込み | **検索（`SearchField`）→ 状態 → 種類 → 期間 → 実行者**。検索の右はすべて `FilterSelect`（#1933。「状態: すべて」の形）。条件はすぐ適用し、作業状態（URL か sessionStorage）に残す | 状態の `ToggleChip` の並び: Agent は 6 つで `FILTER_CHIP_MAX_OPTIONS`（5）を超え、3 製品で形が分かれる。**条件の保存（saved views）**: 3 製品の利用規模では要らない |
| 期間 | すべて（既定）/ 過去 24 時間 / 過去 7 日 / 過去 30 日。backend には `since`（ISO 8601、`runPeriodSince`）で渡す | 任意の範囲（日付の欄 2 つ）: 一覧の 1 行に収まらない。要るなら段 2〜4 の後で足す |
| 件数・ページ送り | `ListToolbar` の `ListCount`（「全 N 件」「N 件（全 M 件）」）+ 表の直下の `OffsetPagination`（サーバーの offset 型、表示件数 10 / 25 / 50 / 100、既定 `DEFAULT_PAGE_SIZE` = 25。#1952）。新しい順 | カーソルの「さらに読み込む」（Phoenix）: 総数とページ番号の入力が無く、監査で「何件目」を指せない |
| 行の操作 | `RowActionMenu` 1 つ（再実行・停止・承認など）。詳細の概要の `ObjectActionBar` と同じ定義 | 行の中のボタン: 行の高さと表の幅を取る |
| 詳細の構成 | **概要 → 回答 → 処理の経過 → 根拠 / SQL / 検証 → フィードバック → 技術的な詳細（畳む）** を縦に 1 枚（`RunDetailLayout`） | **タブ**（RAG・NL2SQL の今の形）: 根拠・処理の経過が隠れ、ページ内検索・印刷・読み上げで届かない。長い Agent の処理の経過は、段の中身を畳んで短くする |
| 処理の経過 | `RunTimeline`: 1 行 = 1 段（ツールの呼び出しは字下げ）、状態のアイコン・名前・所要時間（文字）と、全体の中の位置と長さの線（ウォーターフォール）。中身（引数と結果・SQL・エラー）は行を開く。失敗した段は最初から開く | 段の表（RAG の今の形）: 時間の比較が数字の読み比べになる。**グラフ・ズーム**（Langfuse・OpenAI）: 3 製品の段は数〜数十で、1 画面に収まる |
| 狭い画面（375px） | 一覧は表のまま 2 列（題名・操作）にし、状態・開始日時・所要時間・種類・実行者を題名の下の 1 行にまとめる（container query 56rem）。処理の経過は線を隠す（40rem）。概要の事実は 1 段 | カードのリストに作り替える（Polaris）: 表と別の DOM を持つと、e2e・読み上げの規則が 2 つになる |

## 2. 一覧

```text
┌ PageHeader「実行履歴」 ───────────────────────────────── [最新情報を取得] ┐
┌ Card「実行履歴」 ─────────────────────────────────────────────────────────┐
│ [🔍 質問・実行 ID を検索] [状態: すべて▾] [種類: すべて▾] [期間: すべて▾] [実行者: すべて▾]  全 123 件 │
│ ┌ RunHistoryTable ──────────────────────────────────────────────────────┐ │
│ │ 質問              │ 状態   │ 種類   │ 実行者 │ 開始日時         │ 所要時間 │ … │ │
│ │ 先月の売上は？    │ ✓ 完了 │ チャット│ 自分   │ 2026/10/15 09:12 │   3.2 秒 │ ⋯ │ │
│ │ 販売分析          │        │        │        │                  │          │   │ │
│ └───────────────────────────────────────────────────────────────────────┘ │
│ [1–25 / 123 件] [表示件数 25 件▾]           [«] [‹ 前へ] [ 1 ] / 5 ページ [次へ ›] [»] │

```

375px（表の置き場所が 56rem 未満）:

```text
│ 質問                                   │    │
│ 先月の売上は？（2 行まで）             │ ⋯  │
│ 販売分析                               │    │
│ [✓ 完了] 2026/10/15 09:12  3.2 秒  チャット │    │
```

- **列**（`RunHistoryTable`）: 質問（`RowTitleButton`。`href` 付きのリンク、2 行で切り詰め、全文は Tooltip と詳細。下に対象の名前）/ 状態 / 種類（1 種類しかない一覧は出さない）/ 実行者（他の人の実行が見える利用者だけ。自分は「自分」）/ 開始日時 / 所要時間（右寄せ・等幅数字、実行中・記録なしは「—」）/ token / 費用（記録している製品だけ。記録なしは「—」で 0 にしない）/ 製品の列（2 つまで。RAG の回答の対応、NL2SQL の行数など。狭い画面では出さない）/ 操作。
- **状態**: 製品の状態を共通の 7 つに写す（下の表）。製品に固有の言い方は文言だけを上書きする（Agent の waiting →「承認待ち」）。
- **絞り込み**: `RunHistoryToolbar`（`ListToolbar` を包み、並び・既定・「条件をクリア」・3 つ以上のシートを固定する）。左に検索欄（質問・実行 ID。debounce・IME は `SearchField`）、その右に `FilterSelect` を「状態 → 種類 → 期間 → 実行者」の順（無い条件は飛ばす）。選択肢は共通の値（`RUN_PERIODS` / `RUN_EXECUTOR_FILTERS` と各製品の状態・種類）、既定はすべて「すべて」。条件を変えたら 1 ページ目へ戻す。0 件は「条件に一致する実行がありません」と条件のクリア（#1933）、そもそも 0 件は `EmptyState`（「まだ実行がありません」と、実行を始める画面の案内）。
- **件数・ページ**: 上の表のとおり。5 秒などの自動の再取得で行が変わってもページは戻さない（戻すのは条件を変えたときだけ）。
- **行**: 題名のリンク（Tab → Enter）が主な導線、行のクリックは補助（`onRowClick`）。詳細から戻ったら、開いていた行に `aria-current` と選択の面を付ける（`selectedRunId`）。
- **読み込み中**: 初回は `TimedLoadingState`（「実行履歴を読み込んでいます」+ 経過時間）+ `TableSkeleton`（列は 4）。再取得は前の一覧を出したまま、`PageHeader` の「最新情報を取得」の `loading`。
- **失敗**: 一覧の位置に `ApiErrorBanner`（再試行付き）。前の一覧があれば出したまま。

### 状態の写し方

| 共通の状態 | 文言（既定） | 色 / アイコン | RAG | NL2SQL | Agent |
|---|---|---|---|---|---|
| `queued` | 待機中 | neutral / `Clock` | — | — | `queued` |
| `running` | 実行中 | info / `CirclePlay` | （実行中の記録があれば） | — | `running` |
| `waiting` | 応答待ち | warning / `CirclePause` | — | — | `waiting_approval`（「承認待ち」）・確認の回答待ち |
| `succeeded` | 完了 | success / `CircleCheck` | `success` | SQL を実行・生成できた | `completed` |
| `blocked` | ブロック | warning / `ShieldAlert` | `blocked`（ガードレール） | 安全性の判定で止めた | — |
| `failed` | 失敗 | danger / `CircleX` | `error` | 生成・実行の失敗 | `failed` |
| `cancelled` | 停止 | neutral / `CircleSlash` | 利用者が止めた | 利用者が止めた | `cancelled` |

回答の質（RAG の回答の対応・検証、NL2SQL の評価）は状態に混ぜず、詳細の概要のバッジ（`badges`）と、要るなら一覧の製品の列に出す。

## 3. 詳細

```text
┌ PageHeader「実行の詳細」  ← 一覧へ戻る ───────────────────── [最新情報を取得] ┐
┌ 概要  [✓ 完了] [根拠あり]                         [再実行] [その他の操作 ▾] ┐
│ （失敗・ブロックの理由の Banner）                                            │
│ 質問                                                                         │
│ 先月の売上を地域別に教えて                                                   │
│ 開始日時 2026/10/15 09:12:05  所要時間 3.2 秒  種類 チャット  実行者 管理者  │
│ 会話の持ち主 山田  業務プロファイル 販売分析  モデル openai.gpt-oss-120b      │
│ token 2,000  費用 $0.01  （製品の事実）  実行 ID run-123                     │
└─────────────────────────────────────────────────────────────────────────────┘
┌ 回答 ───────────────────────────────────────────────────────────────────────┐
┌ 処理の経過  5 ステップ・合計 3.2 秒 ─────────────────────────────────────────┐
│ ✓ 質問を分類        ▕██            ▏ 0.4 秒                                  │
│ ✓ SQL を生成   ›    ▕  ████████    ▏ 2.1 秒                                  │
│ ✗ SQL を実行   ⌄    ▕          ██  ▏ 失敗 · 0.3 秒                           │
│     ORA-00942: 表またはビューが存在しません                                   │
┌ 根拠 / SQL と結果 / 検証 / 成果物（製品の節）──────────────────────────────────┐
┌ フィードバック ─────────────────────────────────────────────────────────────┐
┌ › 技術的な詳細（既定で閉じる）───────────────────────────────────────────────┐
```

- **戻る**: `PageHeader` の `back`「一覧へ戻る」（読み上げ名「実行履歴の一覧へ戻る」）。戻ると絞り込み・ページ・スクロールを保つ（workspace-state.md）。ブラウザの戻るも同じ。対象が無い・見えない（404 / 403）は「この実行は見つかりません」と一覧へ戻る案内（別の実行に置き換えない）。
- **概要**（`RunSummary`）: 見出しの行に状態（`RunStatusBadge`）と製品のバッジ、右に対象への操作（`ObjectActionBar`。再実行・停止・承認・フィードバックなど。非破壊の 2 つまでを直置き）。失敗・ブロックは理由の `Banner`（`alert`）を質問の上に。質問は全文。事実は「開始日時・終了日時・所要時間・種類・実行者・会話の持ち主（実行者と違うときだけ。#1954）・対象・モデル・token・費用・製品の事実・実行 ID」の順で、記録の無い事実は並べない。
- **回答**（`RunDetailSection`）: 最終の出力。RAG は引用付きの回答、NL2SQL は回答の文（あれば）、Agent は最終の回答と成果物の要約。回答を作らない実行（RAG 検索だけ・SQL の生成だけ）は節を出さない。
- **処理の経過**（`RunDetailSection` + `RunTimeline`）: 段（`ChatProgressStep` と同じ名前と状態）とツールの呼び出し（`level: 1`）。中身（引数と結果・SQL・エラー・再試行）は行を開いて見る。実行中の実行は 5 秒ごとに取り直し、実行中の段は `Spinner`。
- **根拠 / SQL / 検証**（製品の `RunDetailSection`）: RAG は根拠（引用の一覧と根拠の構成）、NL2SQL は SQL（コードブロック + `ContentActionBar` のコピー）と結果の要約（行数・列。行は保存しない）、Agent は承認・確認の記録・成果物（`ResultTable`）・最終の検証。
- **フィードバック**: その実行への評価の一覧（RAG・NL2SQL）。無ければ節を出さない。
- **技術的な詳細**（`RunDetailSection collapsible`、既定で閉じる）: 実行 ID 以外の識別子（trace・会話・API キーの名前）、モデルの設定、イベントの記録、エラーの全文。生の JSON は `<pre data-surface="code">`。
- **読み込み中**: `TimedLoadingState` + `RunDetailSkeleton`。

## 4. 実行者と会話の持ち主（#1954）

- 一覧の行は、実行した人と会話の持ち主の両方に出る（system_admin は全件。backend が絞る）。
- 「実行者」の列と絞り込み（すべて / 自分が実行 / 他の人が実行）は、他の人の実行が見える利用者（system_admin と、自分の会話で他の人が実行した行を持つ利用者）に出す。自分の行は「自分」。
- 詳細の概要は「実行者」と、実行者と違うときだけ「会話の持ち主」。削除済みの利用者は「削除済みのユーザー」（UUID を出さない）。

## 5. キーボードと読み上げ

- Tab の順: 「本文へスキップ」→ ヘッダーの操作 → 検索欄 → 絞り込み → 表（スクロールの領域）→ 行の題名のリンク → 行の操作 → ページ送り。
- 表は `DataTable` の `stickyHeader` + `visibleRows`（`scrollAriaLabel` で名前付きの region）。題名の列が行の見出し（`<th scope="row">`）。
- 状態は形の違うアイコン + 文言（色だけにしない）。処理の経過の完了の段は状態を読み上げだけ、失敗・スキップ・応答待ちは画面にも文字で出す。時間の線は飾り（`aria-hidden`）で、所要時間は必ず文字。
- 処理の経過の行の開閉は `button[aria-expanded][aria-controls]` + `DisclosureChevron`。技術的な詳細は `Disclosure`（`<details>`）。

## 6. 部品と製品の分担

| `packages/ui` | 製品 |
|---|---|
| `RunHistoryTable`（列・順・狭い画面・リンク・行の操作の置き場所）、`RunHistoryToolbar`（絞り込みの並び・既定・クリア・狭い画面のシート）、`RunStatusBadge`（7 つの状態の色と形）、`formatRunDateTime` / `formatRunDuration` / `formatRunTokens`、絞り込みの値（`RUN_PERIODS` / `runPeriodSince` / `RUN_EXECUTOR_FILTERS`）と既定の文言 | データの取得（サーバーの絞り込み・offset のページ）、製品の行 → `RunHistoryItem` の写し、状態の写し、i18n の文言、行・詳細の操作の定義（`EntityAction`） |

## 7. 確かめること（段 2〜4 の e2e）

- 1280 / 1920 / 375px・ライト / ダークで、横あふれが無い（`measureHorizontalOverflow`）、`PageHeader` と本文の左端がそろう。
- 一覧: 読み込み中（`TimedLoadingState` + Skeleton）・0 件・条件で 0 件・2 ページ以上（`jumpToPage`）・表示件数の既定 25。
- 375px（`@responsive`）: 表が 2 列で、状態・日時・所要時間が題名の下に出る（`[data-run-history-compact-meta]` が見える）。
- 詳細: 題名のリンクで開き、「一覧へ戻る」で条件とページが戻る。URL を直接開ける。節の順（`[data-run-detail]` の子）。処理の経過の行を Enter で開閉できる。
- 状態は `[data-run-status]` の値で確かめる（文言・色に頼らない）。
