# ページ遷移・再読込のときの作業状態（Workspace state）

> 3製品共通の原則。どの画面・どの field を保存するか、保存の namespace・期限、検証の spec は、各製品の文書に書く（例：NL2SQL の `docs/frontend-workspace-state-spec.md`）。

## 状態の保持

- **利用者の作業の進み具合は残し、変わるサーバーのデータは検証し直し、実行の意思は確認し直す。** データの再取得と入力のリセットを同じ操作にしない。全項目の無条件のリセット / 無条件の永続化は禁止する。
- 同じユーザー・同じ接続先・同じ対象の作業では、タブ、検索・フィルター・ソート・ページ、展開した項目、一覧へ戻るときのスクロール位置を残す。対象の変更や削除で無効になった位置・項目だけを直し、別の対象へ黙って置き換えない。
- 入力中のクエリ・手で編集したテキスト・未保存のフォームは下書きとして残す。バックグラウンドの再取得で利用者の編集を上書きしない。再読込のための保存は、明示した allowlist と期限を持つ同じタブの一時保存（`sessionStorage`）に限る。全結果・全フォームを `localStorage` にまとめて永続化しない。保存できないときは黙って成功扱いにせず、離脱の保護を出す。
- 生成した結果・取得した構造・実行結果は、時点を持つスナップショットとして扱う。「前回の実行結果」と実行日時を示し、入力が変わったら今の入力は未実行だと示す。以前の結果を今の入力の成功として出さない。
- 一覧・存在・権限・処理の進み具合は取得し直す / 検証し直す。今の情報を出したまま裏で更新してよいが、失敗したときは古い情報であることと再試行の方法を示す。ページに戻っただけで LLM の生成・実行・mutation を送り直さない。進行中の job は ID でサーバーの状態を確かめる。
- 対象の選択は残して存在と権限を検証し直す。削除などの破壊的な一括選択、確認ダイアログ、確認語は、ページを離れる・戻るときに解除する。入力・対象・実行条件が変わった場合も確認を無効にし、backend の認可・確認を迂回しない。
- 一時的な状態と query cache はユーザー / 接続先の context で分ける。logout・認証の失効・アカウントの変更で消し、接続先・対象の context が変わったら他の context の下書き・結果・確認を使い回さない。失効した対象はエラーとして説明し、選択を黙って置き換えない。パスワード・一時的な資格情報は復元しない。
- ブラウザを閉じた後や別のログインで作業を続けるには、明示的な保存（下書き / workspace の機能）として設計する。表示の設定は個人設定として残してよいが、ページ内の一時的な下書きを恒久的な保存の代わりにしない。
- 操作の名前と役割を分ける：`最新情報を取得` は入力を残した再取得、`入力をクリア` は指定した入力の消去、`新しい作業を開始` は作業全体の初期化。新しい作業の開始で未保存の編集を捨てる場合は確認する（[buttons.md §7](./buttons.md#7-命名規則naming)）。
- 回帰テストには、desktop / mobile-375 での行き来・back / forward・再読込、下書きと選択の保持、確認の解除、古い結果の見分け、取得の失敗、logout / context の切替での分離を含める。

## 未保存変更の離脱ガード

- `isDirty` を使う編集画面は、画面内の「戻る」だけでなく、サイドナビ・内部リンク・再読込・タブを閉じる操作を含む**すべての離脱の経路**を共通の guard で守る。dirty の判定は、順序に意味のない集合 / 配列を正規化して比べ、保存に成功したら保存済みの基準と確認の状態を更新する。
- 3製品とも data router（`createBrowserRouter` + `RouterProvider`。既存の `<Routes>` は 1 つの splat route の中にそのまま置く）で動かす（#138）。共有の `useUnsavedChangesGuard` は次の 3 経路を守る。
  - 内部リンク：click を capture 段階で受けて確認する。修飾キー付きのクリック、`target="_blank"`、download、外部の origin、同じ URL は妨げない。
  - 再読込・タブを閉じる：`beforeunload`。
  - ブラウザの back / forward：`useBlocker` で `historyAction === "POP"` の移動だけを止めて確認し、キャンセルなら URL を元に戻す。
- 画面内のボタンが自分で確認してから `navigate` する流れ（PUSH / REPLACE）は hook で止めない（二重に確認しないため）。そのようなボタンは、移動の前に必ず同じ確認を通す。
- 共有パッケージの画面（`@engchina/production-ready-system-settings` など）は、離脱の確認の文言を props（`draftGuardMessages` など）で受け取る。
