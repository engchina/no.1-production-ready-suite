# 確認・回答ルール

検索・回答プロファイルの知識で管理する補助指示です。KB の所属や文書の処理レシピには設定しません。作成・更新・有効切替・確認の設定は、従来と同じプロファイル管理の権限で認可します。

| 設定 | 作用 | 未設定の既存値 |
|---|---|---|
| 用途 `purpose` | `confirmation` は回答前の確認だけ、`generation` は生成の指示だけ、`both` は両方 | `both` |
| 種類 `instruction_kind` | `presentation` は表現、`requirement` は説明の観点、`verification` は資料で検証する事項 | `requirement` |
| 排他グループ `exclusive_group` | 同じ段階・同じグループは最高優先度を選ぶ。空なら併用 | 空 |
| 適用優先度 `priority` | 大きい整数を先に扱う。候補の照合点数とは別 | `0` |

確認だけならルール内容を空で保存し、その後で確認を設定できます。生成を含む用途では内容が必要です。生成だけに変えても保存済みの確認は削除せず、実行しません。無効にすると両方を使いません。旧 API からの更新で新設定を省略した場合は、保存済みの用途・種類・排他グループ・優先度を保持します。DB の名称や schema_version は変えず、既存値を自動分類しません。

候補は、当該プロファイル内の有効なルールを質問と照合して求めます。確認・生成の段階ごとに、用途と設定の有無、明示優先度、排他グループ、完全に同じ指示の重複、既存の適用件数の上限を確認します。確認を設定していない生成ルールは、確認段階の排他選択に入りません。同順位の排他設定が異なる場合はグループ全体を保留し、両立するほかのルールで回答を続けます。管理者は照合テストに出る保留の案内を見て設定を見直します。管理設定の競合について、利用者へ状況の確認を要求しません。

グループを指定していない自由文の意味上の矛盾までは自動検出しません。「短く書く」と「全手順を説明する」を語の一致だけで矛盾とは判定しません。追加のモデル判定は行いません。ルール内容は上位の指示・権限・利用者の明示条件を上書きせず、資料の根拠や確認済みの事実にもなりません。

実行記録の既存 `runtime_knowledge` payload に `rule_applications` を保存します。候補ごとの ID・内容と設定の hash による版・適用段階・採否・理由・優先度・排他グループを記録します。`matched_rules` は実際に選んだ内容のスナップショットです。条件解決で内容を置換したときも、保存する hash は実際の内容に対応させます。過去の回答は保存済みの内容を読み、現在のルールを適用し直しません。新しい保存基盤・公開ログ・管理権限は追加しません。
