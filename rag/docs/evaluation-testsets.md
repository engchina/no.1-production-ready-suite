# テストセットの管理と評価

「品質評価」の「テストセット」では、人が確認した質問・標準回答・根拠を保存し、同じ条件で繰り返し評価できます。1 人で 1 問から使えます。公開の操作はありません。

## 作成する

「テストセットを作成」で名前と作成方法を選びます。

- **評価結果から作る**: 本人が実行した完了済みの評価を選び、収録する項目を明示選択します。同じ質問でも元の評価や比較条件が異なる項目は自動統合しません。
- **Excel から取り込む**: 既存の評価リクエストの `.xlsx` を選び、プレビューと検証を確認して保存します。取り込んだ項目はすべて未確認です。
- **空のテストセットから作る**: 空のセットを保存し、「質問を追加」で手入力します。追加項目も未確認から始まります。

## 確認する

編集画面の題名はテストセット名で、左上から一覧へ戻れます。desktop は左に項目、中央に編集、右に参考回答と根拠を並べます。携帯は項目の選択と「編集」「参考」のタブを使います。切り替えても入力と読み取り位置を保ちます。

1. 質問・標準回答・期待する根拠を確認します。通常の回答を期待する項目は質問と標準回答が必須です。「確認」「保留」は標準回答なしで確認できます。根拠が空の場合、根拠の取得率などは評価できません。
2. 生成された回答は参考です。「標準回答に使う」を押した場合だけ編集欄へ写します。自動で正解にせず、確認状態も変えません。
3. 「保存して確認し、次へ」で、同じ内容の保存と明示確認を一度に確定して次の未確認項目へ進みます。「下書きだけ保存」は確認状態を進めません。
4. 必須の回答要点・期待する応答の判断・回答の過程は「詳細設定」にあります。
5. 複数項目を確認するときは項目を選び、件数を示す確認ダイアログを通します。不足する必須値があれば確認できません。

確認済みの内容を編集すると未確認に戻ります。次の評価から除外されるため、修正後に再確認してください。保存に失敗した内容は保持し、再試行できます。未保存のまま離れる場合は破棄の確認を出します。別画面で更新された版は 409 で拒否し、上書きしません。

## 評価する

一覧か編集画面の「確認済み N 問で評価」から既存の評価設定へ進みます。評価するプロファイル・回答モデル・比較条件を確認し、「評価実行」を押します。実行設定から保存したテストセットを直接選ぶことも、従来どおり Excel をアップロードすることもできます。

確認済みと除外する未確認の件数を表示します。backend が本人の指定した revision を読み、確認済み項目だけを実行入力へ確定します。ケースを混ぜた要求と古い revision は拒否します。実行時の質問・標準回答・根拠などの六列は原本の保存先へ固定し、job がその原本を参照します。後でセットを編集しても、過去の評価の入力と結果は変わりません。原本を保存できなければ実行を開始しません。

回答モデルは登録済みのモデルだけを選べます。未指定はプロファイルの既定を使います。未知の ID を既定のモデルへ置き換えません。

## Excel と保存

「テストデータをダウンロード」は保存した確認済み項目だけを書き出します。既存テンプレートの六列（質問／期待する根拠／標準回答／必須の回答要点／期待する応答の判断／回答の過程）を維持します。文書 ID・ページ・シート・行・章節・抜粋は既存の reader と同じ表記です。セルは文字列で出力し、先頭の `=` を式として実行しません。

保存先は既存の `rag_evaluation_testsets` と原本の保存先を使い、DDL の変更はありません。テストセットは本人と tenant で分離し、構成管理者でも他人の項目を編集・続行できません。Oracle 未設定の開発用 memory 保存はプロセス限りです。元の評価が削除されても、セット作成時の入力と参考を保持します。
