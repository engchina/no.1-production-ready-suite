# 評価結果からテストセットを作る

「品質評価」の「テストセットの作成」では、本人が実行した完了済みの評価から、標準回答を確認・修正して評価用の Excel を作れます。1 人で 1 件から使えます。評価器の校正とは用途が異なり、記入者の一致や最低件数を要求しません。

1. 「新しい下書きを作る」で名前を入力し、元にする評価を一つ以上選びます。
2. 評価の項目を表示し、整理する項目を選びます。初期状態では未選択です。同じ質問でも評価や比較条件が異なる項目を自動統合しません。
3. 選んだ項目で下書きを保存し、「質問」「標準回答」「期待する根拠」を確認・修正します。その他のテンプレート列は「詳細設定」にあります。
4. 生成された回答は参考です。「標準回答に使う」を押した場合だけ標準回答欄へ写します。その後、項目ごとに「この項目の収録を確認する」を押してください。
5. 「テストデータをダウンロード」で確認済みの項目だけを書き出し、「評価の実行」でそのままアップロードします。未確認の項目は下書きに残ります。

通常の回答を期待する項目は、質問と標準回答が必要です。詳細設定で「確認」や「保留」を選ぶ場合は、標準回答が空でも収録を確認できます。期待する根拠は一律必須ではありませんが、未入力では根拠の取得率などを評価できません。必須の回答要点も、指定しない要点の網羅は評価しません。

下書きは明示して保存します。編集画面の保存操作の行に、保存済み・未保存・保存中・保存失敗の状態を表示します。保存に失敗した内容は保持し、再試行に成功すると保存済みに戻ります。保存済みと、項目を収録するための明示確認は別の状態です。保存前に離れると変更を破棄するか確認します。入力の変更は収録の確認を解除するため、保存してもう一度確認してください。保存済みの下書きは再ログイン後にも開けます。元の評価が後から削除されても、選んだ時点の入力と参考の写しを保持します。元の入力が保存されていない古い評価では、その旨を表示し、不足を自動補完しません。

下書きの作成・編集・続行・出力は本人だけです。構成管理者でも他人の下書きは編集・続行できません。同じ下書きを別画面で更新した場合、古い版で上書きせず開き直しを求めます。

## ファイルと保存

出力は既存テンプレートの六列（質問／期待する根拠／標準回答／必須の回答要点／期待する応答の判断／回答の過程）と同じ契約です。文書 ID、ページ範囲、シートと行、章節、抜粋は既存の reader と同じ表記を使い、セルは文字列として出力します。式として実行しません。回答の過程はテンプレートへ保持されますが、それだけで実行用の期待条件に自動変換しません。

本人の下書きは `rag_evaluation_testsets` に保存します。Oracle 未設定の開発用 memory 保存はプロセス限りです。追加 migration は既存の校正データを書き換えません。

## 以前の校正データ

「以前の校正データ」は閲覧と保管用の書き出し専用です。既存の権限による閲覧範囲を保ち、編集・裁定・校正・削除・取り込みは画面から行いません。既存 API の書き込み操作は `410` を返します。

保管用 JSON は形式「以前の校正データ」、形式の版 `1` です。未確定の記入、元の識別子と管理用情報も残します。このファイルは評価の実行にアップロードする Excel や、CLI の最終ラベル入力の代わりではありません。過去データを自動で新しい正解へ変換しません。

最終判定済みの既存 `export` API と、suite の校正 CLI・日本語／英語のラベルファイル reader は維持します。suite の件数・一致率などの校正基準は変更しません。
