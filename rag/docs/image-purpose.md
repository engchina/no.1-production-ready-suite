# 画像の用途と解析版

画像の用途は、文書解析設定の画像解析で全体の既定を指定し、文書の処理レシピで継承または上書きする。新しい設定の既定は `record`（実データ・記録）、説明用の画像は `example`（画面例・説明用）を指定する。画像単位の上書きや用途の自動分類は行わない。

API の名前は `vision_image_purpose`。全体の設定の更新で省略・null は現在値を保ち、レシピの null は全体の既定を継承する。`unknown` は設定できる値ではなく、過去の解析版に用途の記録がないことを表す読み取り状態である。

解析を開始した実行は設定のコピーを持つ。用途は抽出の ID と Vision の途中再開キーに含め、新しい解析版の `parser_artifacts.vision_image_purpose` と画像の要素・asset・layout record に設定由来の値を保存する。モデルの同名の出力を設定値として扱わない。Vision の無効・失敗は読み取りの状態であり、用途とは分ける。

設定の保存だけで過去の成果物を書き換えない。用途の変更を適用するには再解析する。過去の成果物の missing・null・不正値は `unknown` として読み、現在の全体設定や `record` で補完しない。

原生の本文・表は、画像の用途を指定しても画像由来の事実へ変更しない。画像補足を持つ表の用途は補足画像に対するもので、表のネイティブ本文を一括して説明用の例として扱わない。

画像由来の chunk と根拠は保存された用途を引き継ぐ。用途の指定だけで画像認識の正確性や質問への適用が保証されるわけではない。説明用の値・状態を実在の記録と混同しない回答側の利用は、画像の読み取り構造と准入の検証を含む同一機能の受入条件であり、設定・metadata の決定論テストとは分けて確認する（#4435）。
