# 言語資源の完全な保存契約（#4194）

公開版と下書きは、現行の `rag_parser_core.language.FIELD_SPECS` にある項目をすべて含む保存スナップショットとして扱います。読み取り時に組み込み値で欠測を埋めたり、廃止した項目を取り除いた別内容を実行へ渡したりしません。完全な原値と現行の内容hash・取込hashが一致しない保存物は明示的に失敗します。

組み込み値は、公開版がまだ存在しない新しい環境の初期化にだけ使います。公開版の不正・破損を捕まえて組み込み値に置き換えることはありません。旧ファイルから値を暗黙に移す処理も行いません。

## 配備前のデータ準備の門禁

この契約へ切り替えるコードのmerge・配備は、次の準備を終えるまで保留します。CIの合成fixtureが通ることは、対象環境の保存データが完全であることの証明ではありません。

1. 明示的に指定した対象環境で、現在の公開版、下書き、すべての保存公開版、旧実行・抽出・chunkから参照される版の閉包を**読み取りだけ**で確認します。保存JSONの項目集合・原値・両hashを現行契約と比較します。APIの有効値は既に補完されている可能性があるため、保存原値の確認と区別します。
2. 既存の旧ファイルがある場合、Oracle公開版の有無と独自設定の所在を確認します。新環境のbuiltin初期化を、旧ファイルの独自値を捨てる移行として使いません。
3. 欠測、廃止項目、不正形式、hash不一致を分類し、読み取れなくなる画面・処理と影響する履歴を具体化します。新しい完全な現在版を発行するだけでは、旧履歴の一覧・過去版の処理固定まで復旧しない点に注意します。
4. 独自値を保つ準備方法、対象環境、変更する下書きや新規公開版、履歴・過去成果物の扱いをレビュー可能な形にします。既存公開版の内容やhashを後から書き換えたり、版を偽造したりしません。
5. 実際のデータ書込み・新規公開・削除・再解析は利用者の別の明示許可を得てから行い、コード修正のテストとして実行しません。準備できないデータが残る場合、互換fallbackを隠して復活させず、コードの切替を保留します。

この文書や合成テストはデータ移行を実行しません。DBの表定義、認可、版/来歴のfail-closed、索引の版切替の規則は変更しません。
