# アップロード保存先のマニュアル検証記録

確認日：2026年10月28日（日本時間）。実装照合元：`d3e05b4729`。対象は RAG「システム設定 → アップロード保存先」です。

## 実画面の操作

実際の RAG に専用の Chromium コンテキストでログインし、Playwright で確認しました。APIの成功応答や画面をモックへ差し替えていません。

| 操作 | 結果 |
|---|---|
| 左ナビと設定画面の表示 | 見出し「アップロード保存先」、区画「保存先」を確認 |
| 保存先の切替え | ローカルとOCIで入力欄が切り替わる。初期の保存済み選択はローカル |
| ローカルの合成入力 | `/検証用/架空サンプル/原本保存` を入力して表示確認。ディレクトリ作成・保存はしていない |
| namespace欄 | 読み取り専用であることを確認 |
| OCI接続確認 | 既存の設定に含まれるバケットに対して1回実行。HTTP 200で結果statusはfailed。OCI認証の設定はsuccess、bucketはfailed、write/read/deleteはskipped。HTTP 404相当の説明を表示 |
| 合成バケット名の形式エラー | 日本語の架空値を入力して「接続を確認」を押すと、文字種のエラー。以降の接続確認リクエストは0件 |
| 変更の破棄 | 左ナビ選択でalertdialog「変更を破棄しますか」を表示し、「キャンセル」で元の画面に留まることを確認 |
| 幅1440pxと375px | 入力欄とエラーを実画面撮影。375pxで横方向のはみ出しなし |
| 既存設定の保護 | 保存のPATCH要求0件。予防的なPATCH遮断の発動0件。再読込時に設定GETのdataが開始時のdataと一致 |
| 終了時 | 合成入力を再読込で破棄し、ログアウト、Cookie削除、ブラウザー終了 |

「接続を確認」は設定保存ではないものの、バケットに確認専用オブジェクトを作成・読取・削除する外部副作用があります。初回の実行案は自動承認審査で拒否され、送信していません。その後、利用者から「現在登録されているバケットで確認専用オブジェクトの新規作成・読取・削除のみ」を行う明示的な許可を得て実行しました。

実際にはバケットの確認段階で404となったため、オブジェクトの書込み・読取り・削除へは進んでいません。接続先のバケットが存在しないのか、参照権限が不足するのかは、この結果から断定していません。画面は失敗と未実施を区別して表示しました。

## 未実施の範囲

- ローカル保存先・OCI保存先の保存。成功通知と再表示による永続化は実装照合のみ。
- ローカルディレクトリの作成、書込み権限と容量の確認。
- OCI接続確認の書込み・読取り・削除、および全段階の成功。
- OCI設定不足の警告、タイムアウト等による保存済み・接続未確認の警告の再現。
- 変更破棄ダイアログで「破棄して移動」を押す操作。キャンセルと再読込みによる破棄は確認済み。
- 添付の合成テキストファイルの文書アップロード・解析・原本表示。この記事の対象画面にはファイル選択欄がないため、補助資料として用意した。
- 既存の原本ファイルの移動・削除・上書き。

## 実装の根拠

リポジトリ内の相対パスです。

- `platform/packages/system-settings/src/upload-storage/UploadStorageSettingsPage.tsx`：保存先切替え、入力中の値でのテスト、形式検証、別々の保存結果・警告。
- `platform/packages/system-settings/src/upload-storage/messages.ts`：実際の表示名、入力エラー、保存通知。
- `platform/packages/system_settings_backend/src/pr_system_settings/upload_storage.py`：候補検証、OCI接続確認、失敗の分類、設定保存後の反映。
- `platform/packages/system_settings_backend/src/pr_system_settings/upload_storage_check.py`：5段階の確認。`.production-ready/storage-check/` 配下にUUID付きの確認専用オブジェクトを作り、読み取り・削除する。
- `platform/packages/system-settings/src/guards/useSettingsDraftGuard.ts`：未保存変更の離脱確認。
- `rag/backend/app/security/permissions.py`：メニューとAPIの権限。
