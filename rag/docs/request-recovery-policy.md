# 生成前と生成後の根拠不足への補救

生成前 CRAG は材料の関連性・十分性を判定する。生成の後に LLM の確認の段は持たず（#4714）、生成が明示した gap をそのまま回答の不足として返す。確かめるのは参照の実在と形式だけである。

検索語の一致や関連する引用元の存在だけで、材料の十分性を確定しない。回答の充足と材料の有無を別のフィールドにすることで、誤った対処を追跡できる。

CRAG の補正検索は既存の `ExtraRetrievalBudget` を使う。`CoverageUsage` は実行した検索文、追加根拠、補正検索に使った時間を後続へ引き継ぐ。CRAG の初回検索は追加検索として数えず、pool 内の局所拡張もネットワーク検索の回数には数えない。章節の原文読取は従来の章節読取予算と回答全体の期限に従う。総入力予算・各段の上限のさらなる整理は #3682 に残る。

## 四条件の比較

既存の比較準備 CLI に `--recovery-matrix` を渡す。

```sh
python -m app.rag.retrieval_budget_plan <EvaluationRunRequest.json> --output-dir ./tmp/recovery-comparison --recovery-matrix
```

出力は CRAG 有無 × 生成後補查有無の四条件。モデル・質問・索引・検索範囲・監査モード・総予算を固定する。要求 JSON の `answer_flow` と全体環境差分を各対象環境に適用し、既存評価 CLI/API で実行する。準備ファイルは実行結果ではなく `executed=false` のままである。常駐 backend へ反映するには設定の適用と再起動が必要。保存済み設定やプロファイルが環境値を上書きしていないことを有効設定の snapshot で確認する。#2573 の段階除去 runner は未実装なので、新規 runner が利用可能とは扱わない。

決定論回帰では四条件の発火、材料不足と回答漏れ、未知、検索失敗、共通予算、無進展停止を確認する。実サービスでの品質・token・費用・p50/p95 の四条件比較は未完了であり、両方を既定 ON にする根拠はない。既定は維持し、効果の実測は #3755 で追跡する。
