# 全文検索が上限に達したときの補完

Oracle Text の式は語の上限（`RAG_TEXT_SEARCH_MAX_TOKENS`。既定 24 語）と文字数の上限（`RAG_TEXT_SEARCH_MAX_QUERY_CHARS`。既定 3,000 文字）の枠を守る。質問に明示された識別子・版・日付・数値条件と項目名を優先し、型番の内部の数字を別の条件として重複配分しない。省略した語と実際の式は `text_search_tokenization_traces` に記録する。語の一致から回答の根拠が十分かを判定しない。

元の質問が上限に達した場合は、質問契約の元の要求 ID ごとに、要求の原文と共通の前置きで補う。検索範囲・分類・確認済み条件は主の検索と同じものを渡す。分割にモデルを使わず、補完検索では文書選択のモデル呼び出しを使わない。

追加の検索は `ExtraRetrievalBudget` の `query_overflow` から数え、業務ガイドと生成後の不足の補查が使う同じ回数の枠を消費する。`CoverageUsage` に検索文・時間・新たに採用した根拠数を記録し、後続の不足の補查でも同じ残りの枠を使う。既検索の原文と同じ検索は再実行せず（同じかは全文検索の語と同じ正規化で、空白（改行・タブを含む）を 1 つの空白として比べる。主の検索の文も改行・タブを空白にした形なので、改行を含む質問も主の検索と同じ原文になる。#5160）、同じ分割文が複数の要求に対応するときは結果を再利用する。失敗も同じ実行内で再試行しない。

`generation_trace.query_overflow` の要求別の記録は次を区別する。

| status | 実行の事実 |
| --- | --- |
| `candidate_found` | 実行し、根拠レコードを取得した。回答の充足を意味しない |
| `no_candidates` | 実行したが、回答用の根拠レコードはなかった |
| `failed` / `reused_failed` | 実行が失敗した / 同じ失敗を再実行しなかった |
| `reused` / `already_searched` | 分割結果を再利用した / 主の検索か先行検索で同じ原文を実行済み |
| `unsearched_budget` / `unsearched_deadline` / `unsearched_evidence_budget` | 共有の回数 / 期限 / 追加根拠数の枠で未検索 |
| `unsearched_query_overflow` | 1 要求と共有条件だけでも保護した語が収まらず未検索 |
| `unsearched_tokenization_failed` | 語の抽出が失敗して未検索 |

要求ごとの検索は、主の検索と同じく「検索 → rerank → 関連度の下限 → 文書ごとの上限 → `top_k` で切る」だけを行う（#5173）。ただし関連度の下限の後・文書ごとの上限の前に、主の検索の根拠にすでにある候補（同じ chunk・並びの親や前後の文脈に含まれる・主の検索の根拠を章節で補う起点の章節に入る）を除き、切りの枠をすべて新しい根拠に使う（#5175。除いた件数は `covered_candidates`、理由は工程「主の検索の根拠と重複する候補の除外」）。`top_k` は、足す根拠の合計（`RAG_REQUEST_COVERAGE_MAX_CHUNKS`）を要求の数で割った件数（切り上げ）と、合計の残りの小さい方（記録の `top_k`）。合計の使用量（`new_candidates`）は、先の要求の検索で採った根拠を数えない。切った根拠（`candidate_chunk_ids`）は、検索拡張の根拠と同じ規則で主の検索の根拠へ合わせる（並びにある・含まれる → 印 `query_overflow` だけ／同じ文書 → 文書の chunk の順の位置／無い → 最後）。主の検索の根拠（起点と前後・親の文脈）は外さず（主の検索の根拠の前後の文脈は主の検索の原文だけから選ぶ。外れたときは外れた根拠と同じ文書の補いの根拠だけを使わず、件数と理由を診断の `supplement_merge` と工程「補いの検索の根拠の合わせ込み」に残す。#5185）、合わせた後に文脈の補完（章節の拡張を含む）を 1 回だけ行う。新たに足した根拠（印だけのものを除く。主の検索の根拠のかたまりにまとめられて文脈の役割になったものは含む）の ID は `added_chunk_ids` に記録する。業務ガイドの手順ごとの検索も同じ除外・切り・合わせ込み（[rag-engine.md の「補いの検索と 3 つの経路」](./rag-engine.md#補いの検索と-3-つの経路5173)）。回答・検索だけ・MCP の `rag_retrieve_evidence` のどの経路でも行う。

原質問だけで検索する設定（`RETRIEVAL_ORIGINAL_QUERY_ONLY`）では追加の分割を行わない（`skipped=original_query_only`）。一つの要求と共有条件の保護語だけで上限を超える場合は、条件の組み合わせを推測して検索しない。未検索は「資料に無い」と扱わない。

決定論テストは範囲・回数・期限・記録の契約を確かめるもので、検索品質を証明しない。実 Oracle と同一条件のモデル比較（既存の #2573 の比較基盤を使用）による Recall・呼び出し数・負荷・p95 の検証は別に行う。
